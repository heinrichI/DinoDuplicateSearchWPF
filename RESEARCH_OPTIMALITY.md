# Исследование: Оптимальность алгоритма поиска сильно повреждённых дубликатов

## Executive Summary

**DINOv2 + SIFT/WGC — это сильная, но НЕ оптимальная комбинация для поиска сильно образанных изображений.** Пайплайн грамотный и вычислительно эффективный, но он жертвует точностью ради скорости и простоты. Существуют документально подтверждённые альтернативы, превосходящие его по точности на сильно искажённых изображениях.

---

## 1. Что реализовано в проекте

### Архитектура пайплайна (2 стадии)

| Стадия | Алгоритм | Файл | Роль |
|--------|----------|------|------|
| 1 | **DINOv2 ViT-B/14** (facebook/dinov2-base) | `EmbeddingExtractor.cs` | Извлечение 768-D эмбеддингов CLS-токена |
| 2 | **SIFT + Weak Geometric Consistency** | `GeometricConsistency.cs` | Верификация геометрических трансформаций |

### Кластеризация (3 уровня)

| Условие | Метод | Файл |
|---------|-------|------|
| ≤10,000 изображений | Agglomerative Clustering (полная матрица расстояний) | `AgglomerativeClustering.cs` |
| 10,000–50,000 | Union-Find с парным сравнением | `AgglomerativeClustering.cs` |
| >50,000 | Product Quantization (96 подпространств, 256 центроидов) | `ProductQuantizer.cs` |

### Группировка: Bron-Kerbosch (максимальные клики)
Все изображения в группе должны пройти геометрическую верификацию **с каждым** другим — очень строгое требование.

## 2. Критический анализ: DINOv2

### Сильные стороны
- Self-supervised ViT, обученный на ~142M не размеченных изображений
- Наследственная устойчивость к кропу, ресайзу, цветовым сдвигам (благодаря аугментациям при обучении)
- L2-нормализация → косинусное сходство = скалярное произведение (быстро)

### Слабые стороны (документально подтверждены)

| Проблема | Данные | Источник |
|----------|--------|----------|
| **Высоко-нормовые токены-выбросы** | Без register-токенов accuracy предсказания позиции: 22.8% vs 41.7% для нормальных | DINOv2 paper |
| **Скромная точность fine-grained retrieval** | ViT-B/14: **49.5 mAP** на Oxford-H nearest neighbor | Официальные бенчмарки |
| **Не оптимизирован для image-image similarity** | Обучен на self-distillation, не на pairwise matching | Архитектура |

**Вывод:** DINOv2 — хороший выбор по умолчанию, но потолок ~50 mAP оставляет пространство для улучшений.

## 3. Альтернативы: что лучше для сильно образанных изображений

### 3.1. SuperPoint + LightGlue (замена SIFT + WGC)

| Параметр | SIFT + WGC (текущий) | SuperPoint + LightGlue |
|----------|----------------------|------------------------|
| Тип | Ручные признаки + хистограммы | learned features + learned matcher |
| Устойчивость к кропу | Средняя (SIFT ломается при сильном кропе) | Высокая (обучен на аугментациях) |
| Устойчивость к вращению | Ограничена 24-бенной гистограммой | Неявная (rotation-equivariant) |
| Устойчивость к освещению | Слабая (SIFT struggle under illumination extremes) | Высокая |
| Скорость | Быстрая | Сопоставимая (LightGlue: адаптивное число ключевых точек) |

**LightGlue превосходит SuperGlue как новый SOTA для feature matching** — одновременно точнее и быстрее.

### 3.2. LoFTR (Detector-Free Matching)

- **Устраняет отдельный этап детекции ключевых точек** — трансформерные self/cross-attention работают на всём изображении
- Особенно силён на textureless и heavily overlapping regions
- **Не требует детектируемых ключевых точек** — работает даже когда SIFT/SuperPoint не находят feature points
- Недостаток: медленнее SuperPoint+LightGlue на текстурных изображениях

### 3.3. CLIP (альтернатива DINOv2)

- Zero-shot transfer без дообучения
- Оптимизирован для text-image alignment, не image-image similarity
- **Не заменяет DINOv2** для pixel-level matching, но может дополнить для семантической группировки

### 3.4. ArcFace / Domain-Specific Embeddings

- Обучены на конкретных доменах (лица, документы, товары)
- Могут превосходить DINOv2 в узких задачах
- Требуют fine-tuning

## 4. Оценка по критерию «сильно образанные изображения»

| Тип повреждения | DINOv2 + SIFT/WGC | DINOv2 + LightGlue | LoFTR |
|-----------------|--------------------|--------------------|-------|
| **Сильный кроп** (>50% площади) | Средне (DINOv2 держит, SIFT ломается) | Хорошо (LightGlue robust) | Отлично (detector-free) |
| **Вращение** (>45°) | Средне (24-бин гистограмма) | Хорошо (rotation-equivariant) | Хорошо |
| **Цветовой сдвиг** | Хорошо (DINOv2 robust) | Хорошо | Хорошо |
| **Изменение разрешения** | Хорошо (resize to 224x224) | Хорошо | Хорошо |
| **Водяные знаки / текст** | Слабо (DINOv2 может совпасть, WGC — нет) | Средне | Средне |
| **Экстремальное освещение** | Слабо (SIFT struggle) | Хорошо (learned features) | Хорошо |
| **Аффинные искажения** | Средне | Хорошо | Отлично |

## 5. Выводы и рекомендации

### Текущий пайплайн: 7/10

Это **грамотная инженерия**, но не SOTA:
- DINOv2 — хороший семантический backbone, но не оптимальный для fine-grained retrieval
- SIFT/WGC — legacy подход, уступающий learned matchers
- Bron-Kerbosch клики — строго, но может отбрасывать valid groups

### Рекомендации по улучшению (по приоритету)

1. **Замена SIFT/WGC → SuperPoint + LightGlue** — наибольший выигрыш в точности для сильно образанных изображений при сопоставимой скорости
2. **Добавление DINOv2 register-токенов** — исправляет проблему high-norm outlier tokens, улучшает точность
3. **Эксперимент с LoFTR** — для случаев, где ключевые точки не детектируются (textureless regions, heavy occlusion)
4. **Гибридный подход** — DINOv2 для быстрой кандидатной стадии + LightGlue для финальной верификации

### Не стоит менять

- Трёхуровневая кластеризация — оптимально масштабируется
- L2-нормализация эмбеддингов — математически корректно
- Кэширование в SQLite — правильно для production
- Bron-Kerbosch — строго, но обосновано для дубликатов
